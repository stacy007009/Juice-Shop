# OWASP Juice Shop: Початкові кроки з веб-безпеки

## Концепція

OWASP Juice Shop — навмисно вразливий веб-додаток на Node.js, Express та Angular, що містить понад 100 челенджів різного рівня складності. На відміну від WebGoat, тут немає покрокових підказок у самому інтерфейсі — сторінку зі списком завдань (Score Board) потрібно знайти самостійно, аналізуючи код застосунку.

## Ціль

Пройти базові рівні: знайти приховану сторінку зі списком завдань, виконати XSS-атаку, знайти конфіденційні файли через обхід фільтрів сервера та отримати доступ до акаунту адміністратора через SQL-ін'єкцію.

## Крок 1. Підготовка (Setup)

Застосунок запущено локально через Docker:
```bash
docker run --rm -p 3000:3000 bkimminich/juice-shop
```
Після запуску відкрито `http://localhost:3000`.

## Крок 2. Пошук Score Board

Посилання на список усіх челенджів у інтерфейсі приховане. Знайдено через інспектор браузера (F12) — у файлі `main.js` серед іншого коду зустрічається рядок, що вказує на маршрут `score-board`.

Пряме посилання: `http://localhost:3000/#/score-board`

![Знайдено сторінку Score Board зі списком челенджів](./screenshots/juiceshop_scoreboard.png)

## Крок 3. Атака на пошуковий рядок (DOM XSS)

**Завдання:** виконати DOM XSS-атаку через поле пошуку.

**Спроба:** у пошуковий рядок введено payload:
```html
<iframe src="javascript:alert('xss')">
```
На практиці перша спроба не спрацювала — застосунок обробив введення як звичайний пошуковий запит і показав "No results found" замість виконання скрипта.

![Перша спроба XSS через пошук — результат не досягнуто](./screenshots/juiceshop_xss_attempt.png)

*Примітка: челендж потребує повторної спроби з коректним екрануванням payload (можливо, через URL-параметр `q=` напряму, а не через поле вводу в інтерфейсі) — залишено як пункт для доопрацювання.*

## Крок 4. Витік конфіденційних даних (Sensitive Data Exposure)

**Завдання:** знайти файл, який не мав би бути публічним.

Спочатку виконано спробу переглянути файл напряму через FTP-директорію (`/ftp/...`), проте сервер повернув помилку — дозволені лише файли з розширеннями `.md` та `.pdf`:

![Помилка сервера: дозволені лише .md та .pdf файли](./screenshots/juiceshop_403_error.png)

**Обхід фільтра (Poison Null Byte):** додано `%2500.md` в кінець назви файлу з забороненим розширенням, що дозволило обійти перевірку типу файлу на сервері та завантажити приховані бекапи:

![Успішно завантажені файли через обхід фільтра Poison Null Byte](./screenshots/juiceshop_poison_nullbyte.png)

Таким чином отримано доступ до кількох файлів (`package.json.bak`, `coupons_2013.md.bak` тощо), що не мали бути публічно доступні.

## Крок 5. Адмінська панель (SQL Injection) — невдала спроба

**Завдання:** увійти в систему без знання пароля через SQL-ін'єкцію в поле Email.

**Хід:** у поле Email введено `1=1--` (без початкової лапки), пароль — довільний.

**Результат:** вхід не виконано, система повернула `Invalid email or password`.

![Невдала спроба SQL-ін'єкції — введено рядок без відкриваючої лапки](https://github.com/stacy007009/Juice-Shop/blob/main/IMG_2697.png)

**Причина невдачі:** пропущено відкриваючу одинарну лапку `'`, яка потрібна для розриву синтаксису SQL-запиту. Правильний payload має виглядати як:
```
' or 1=1--
```
Це залишається пунктом для повторного проходження.

## Підсумковий результат

Незважаючи на невдалі спроби з DOM XSS та SQL Injection, вдалося успішно пройти decilька челенджів рівня Broken Access Control та Security Misconfiguration:

- **Forgotten Sales Backup** — доступ до забутого бекап-файлу продажника
- **Poison Null Byte** — обхід перевірки типу файлу
- **Forgotten Developer Backup** — доступ до забутого бекап-файлу розробника
- **Confidential Document**, **Error Handling** — пройдені раніше в ході дослідження

Загальний прогрес на момент завершення роботи: **6 з 179** челенджів (5% Hacking Challenges).

## Інструментарій, використаний у роботі

| URL-маніпуляції (Poison Null Byte) | Обхід серверної перевірки типу файлів |

## Висновок

Пройдено базові рівні OWASP Juice Shop: виявлено приховану сторінку зі списком завдань, продемонстровано техніку обходу фільтрації файлів (Poison Null Byte) для доступу до конфіденційних бекапів. Спроби DOM XSS та SQL Injection для входу під адміністратором виявились невдалими через помилки у формуванні payload — задокументовано причини та коректний варіант payload для подальшого повторного проходження.
